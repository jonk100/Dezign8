## Overview

`Quote` automatically maps to `<blockquote>` or `<q>` based on `type`, keeping semantic HTML and visual presentation aligned. The `cite` prop sets the standard `cite` attribute on the rendered element.

Default: `type="block"`.

---

## Usage

### Block quote (default)

Renders `<blockquote>` with muted, italic text and a left border.

```astro
<Quote cite="https://example.com">
  Simplicity is the ultimate sophistication.
</Quote>
```

<Quote cite="https://example.com">
  Simplicity is the ultimate sophistication.
</Quote>

---

### Pull quote

Prominent, larger centered text for highlighting key excerpts in editorial content. Still renders as `<blockquote>`.

```astro
<Quote type="pull">
  The best code is the code never written.
</Quote>
```

<Quote type="pull">
  The best code is the code never written.
</Quote>

---

### Inline quote

For quoting within a paragraph. Renders as `<q>`, which browsers wrap in typographic quotation marks.

```astro
<Text>
  As the architect said, <Quote type="inline">we should probably delete that</Quote>, and I agreed.
</Text>
```

<Text>
  As the architect said, <Quote type="inline">we should probably delete that</Quote>, and I agreed.
</Text>

---

## Props API

| Prop | Type | Default | Description |
|---|---|---|---|
| `type` | `"block" \| "pull" \| "inline"` | `"block"` | Visual style and semantic element. `block`/`pull` → `<blockquote>`, `inline` → `<q>`. |
| `cite` | `string` | `undefined` | URL of the quote source. Sets the `cite` HTML attribute. |

Inherits all `TypographyProps` (`size`, `weight`, `color`, `align`, `leading`, `fam`, etc.) and `BaseComponentProps`.

---

## Accessibility

- `block` and `pull` render as `<blockquote>` — screen readers announce these as block quotes.
- `inline` renders as `<q>`, which browsers surround with quotation marks. Do not manually add quotation marks in the slot content.
- Use `cite` to attribute the source where possible.
